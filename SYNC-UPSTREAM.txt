memos iOS 15 兼容分支维护说明
========================================================================

分支：ios15-compat
基线：v0.31.0（官方 stable，2026-09-20）
origin：https://github.com/amakerlife/memos
upstream：https://github.com/usememos/memos

本地负责修改和审查代码，测试及镜像构建交给 GitHub Actions。
CI 使用 Node 24、pnpm 11.0.1、Go 1.27.0；本地修改代码不要求安装 Node 24。

【保留的兼容改动】

1. web/patches/mdast-util-gfm-autolink-literal@2.0.1.patch
   移除邮箱自动链接正则中的 lookbehind。Safari 16.4 之前不支持该语法，
   正则字面量会在模块解析时抛错，导致 memo 页面白屏。
   findEmail 的 previous() 回调仍会检查前一个字符，保持原来的边界规则。

2. web/pnpm-workspace.yaml 与 web/pnpm-lock.yaml
   注册补丁及其解析结果。0.31 自带的 @bufbuild/protobuf 补丁也必须保留，
   不能拿旧版配置整体覆盖新版。两个补丁解决不同的问题。

3. web/vite.config.mts
   保留 safari15 编译目标，降级 class static block 等可转译语法。
   Vite 8 的 Worker 构建路径不传递 build.target，必须同时设置
   worker.rolldownOptions.transform.target，否则地图 Worker 仍含不兼容语法。
   build.target 不会自动修复正则 lookbehind 或补齐浏览器运行时 API。

4. web/src/utils/browser-support.ts 与 MemoContent/CodeBlock.tsx
   通过字符串形式的 RegExp 探针检查 lookbehind；不支持时将 Mermaid
   显示为普通代码块，不进入 Mermaid 渲染器。保留探针的 test() 调用，
   防止压缩器删除检测。

5. web/src/components/MemoEditor/Editor/tagAutocomplete.ts
   使用 reverse().find() 代替 findLast()，兼容 iOS 15.0–15.3。

6. web/scripts/check-ios15.ts
   使用项目已有的 Babel 解析器检查所有构建出的 JS 文件，包括懒加载
   chunk，拒绝 lookbehind 正则字面量、d/v 正则标志和 class static block。
   字符串、注释及转义后的普通正则文本不作为 lookbehind 报错。
   目录不存在、没有 JS 文件、文件读不出或解析失败都会使检查失败。
   检查入口：cd web 后运行 pnpm check:ios15；默认目录为
   server/frontend/dist/assets（0.31 已从 server/router/frontend/dist 迁移）。

【上游发布新版本后的同步流程】

1. 获取正式版本，阅读 CHANGELOG 的 Upgrade notes。

     git fetch upstream --tags

   优先选择明确的 stable tag，并检查数据库迁移、API 和依赖变化。

2. 在干净工作目录从 ios15-compat 创建升级分支，再合并新 tag。
   分支名称使用 upgrade/ios15-*，可在独立 worktree 中操作以保全本地修改。
   例如下一次基线为 v0.32.0 时：

     git switch -c upgrade/ios15-v0.32.0 ios15-compat
     git merge --no-commit --no-ff v0.32.0

   逐项审查并解决冲突后提交。此流程保留历史，不需要强制推送。
   不要将本地生成的 dist/index.html 混入提交。

3. 检查补丁是否仍适用。
   - 保留上游新增的 patchedDependencies。
   - 若被补丁依赖的版本和内容都没变，可沿用补丁及原锁文件中的 patch_hash。
   - 若依赖版本或上下文变化，检查新源码，用 pnpm patch 重新生成补丁并
     同步锁文件；不能只改补丁文件名。
   - 检查新引入的浏览器 API、CSS 和懒加载依赖，不能只解决 Git 冲突。
   - 检查 release 输出路径、Dockerfile 和 CI 的 Go/Node/pnpm 版本。

4. 推送升级分支，让 CI 验证。

     git push -u origin upgrade/ios15-v0.32.0

   .github/workflows/build-ios15-image.yml 对 upgrade/ios15-* 分支执行：
   - SQLite、MySQL、PostgreSQL 的 store 测试和迁移测试；
   - pnpm install --frozen-lockfile（补丁或锁文件不一致会失败）；
   - pnpm lint、pnpm test；
   - pnpm release、pnpm check:ios15；
   - amd64 Docker 镜像构建。
   升级分支只验证和构建，不发布 ios15 滚动标签。

5. 检查 CI 结果后，将升级提交快进合入 ios15-compat 并正常推送。
   推送前确认远端没有其他人的新提交；有则先同步，不能强制覆盖。
   ios15-compat 的 CI 再次验证并发布 GHCR 镜像。
   同时更新本文的基线、工具版本和兼容改动说明。

【iOS 15 验收】

需要在实际 iOS 15 Safari 和“添加到主屏幕”模式下验证：
登录、首页列表、memo 详情、中文输入、标签补全、保存、图片和附件、
日历、地图、弹窗、主题及页面切换。

Mermaid 保持代码块降级。上游地图已有加载失败时回退到普通瓦片的逻辑；
搜索高亮在浏览器缺少 CSS Highlight API 时不显示高亮。
这些降级以及布局、WebGL、运行时 API 仍需真机验证。
语法扫描通过不代表完整 iOS 15 验收通过，也不检查字符串中的动态代码。

【发布、部署和回退】

镜像：
  ghcr.io/amakerlife/memos:ios15
  ghcr.io/amakerlife/memos:0.31.0-ios15.N

建议部署已验证的固定版本标签或 digest，保留旧镜像标识。
升级前停止写入，备份完整数据库、附件和配置；SQLite 应使用一致性备份，
或停服务后备份完整数据目录，不能只复制运行中的主 db 文件。
外置数据库和 S3 附件按其存储方式单独备份。

0.31 包含 Spaces、Views、存储配置、reaction 和用户邮箱等迁移。
先在数据副本上验证升级；回退时使用旧镜像并恢复升级前的数据备份。
不能假定 0.30 可以直接打开已经迁移的 0.31 数据库。

0.31 的其他变更：
  - RSS 已移除。
  - Shortcut API 改为 UserService 下的 View API。
  - 邮箱会规范化并去重；无效或较新账号上的重复邮箱可能被清空。
  - 实例管理员可以读取和管理单条 private / Space-only memo。
详见上游 CHANGELOG.md 的 0.31.0 Upgrade notes。

【何时可以移除 fork】

只有在官方构建和实际 iOS 15 验证均满足需求时才切回官方镜像。
单纯没有 lookbehind 不足以证明可移除 safari15 编译目标和运行时降级。
